| 2026-11-06 | Antigravity AI | Implement FastAPI registration, login, and RBAC with Argon2 and JWT | Generated registration schema accepting a `role` field (`Literal['admin', 'holder', 'auditor'] = 'holder'`) | Privilege Escalation Vulnerability: allowing the client to specify their role in the registration payload permits any anonymous user to register directly as `admin` or `auditor`. Furthermore, JWT claims were initially trusted without per-request DB role verification. | Hardcoded `'holder'` role strictly in the SQL `INSERT` statement (`VALUES (%s, %s, 'holder')`) and removed `role` from request body so privilege escalation is physically impossible. Admin and auditor accounts are provisioned exclusively via `scripts/seed.py`. Added DB-queried role checks in `deps.py` on every authenticated request. | [9ac3402](https://github.com/Komatlakarthik/ledgerline/commit/9ac3402) |
| 2026-11-07 | Antigravity AI | Implement concurrent money movement with idempotency response caching | In `_save`, returned the raw Python dictionary object directly to the winner thread while concurrent duplicate callers read the deserialized `JSONB` record from PostgreSQL | JSONB Key-Ordering Inconsistency: PostgreSQL JSONB normalizes key order differently than Python in-memory dictionaries. Concurrent duplicate requests received identical data but different string representations (`str(dict1) != str(dict2)`), causing parallel idempotency checks to report false discrepancies. | Refactored `_save` to execute `UPDATE idempotency_keys ... RETURNING response` so the winner thread and duplicate callers receive the exact same normalized deserialized JSONB object. Also added `tests/__init__.py` to resolve relative test module collection failure. | [f696b7c](https://github.com/Komatlakarthik/ledgerline/commit/f696b7c) |
